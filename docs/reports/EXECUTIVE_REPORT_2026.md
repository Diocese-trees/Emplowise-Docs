is a service, not software. The client keeps their headcount and their systems.
They gain a named HR owner, written scope and a predictable cadence on a

### The argument in three callouts

**The commercial argument in one line.** A growing company already pays for HR.
It pays in founder hours, in a salesperson who is never reviewed, in a designer
who leaves without a handover, and in a contract that cannot be enforced. The
retainer replaces that spending with a named owner and a written record.

**Scope boundary, stated in the same breath.** Emplowise does not act as a law
firm, does not guarantee compliance or hiring outcomes, does not take board
authority and does not replace the client's management. Recruitment fees,
payroll tax scope, legal qualifications, representative allocation and contract
terms are confirmed in writing after the Free HR Audit.

**Why EmploStart stays free.** It is distribution and goodwill, not a lead
magnet. It asks for no email address and uploads nothing. The bridge to the paid
service is one line in the audit output: hiring instead of job hunting, run the
free HR audit.

### The four dashboard cards and the exact formulas

All formulas below are as implemented in the generator script. `tenure` and
review age are measured in months with a 30.44-day fraction, against the model
date, default 2026-11-23.

**Contract component, per person, 0 to 100.**

```
start at 0
verbal terms                       add 60
probation with tenure over 3 months add 45   (only when not verbal)
fixed-term contract                 add 20   (only when neither above applies)
notice gap = max(0, notice floor minus notice_period_weeks)
add min(40, notice gap times 12)
clamp to 0 to 100
```

**Performance component, per person, 0 to 100.**

```
clamp(((performance floor minus performance_score) divided by performance floor) times 100, 0, 100)
```

**Retention penalty, per person, 0 to 100.**

```
if last_review_date is empty: add min(30, 10 plus tenure times 1.2)
else: add min(24, review age times 1.8), plus 4 when review age exceeds the review window
if tenure is under 6 months: add 8
if risk_flags contains scope_requests_unanswered: add 14
if risk_flags contains pay_flat_24m: add 8
if risk_flags contains promotion_without_criteria: add 10
if contract_status is verbal: add 6
clamp to 0 to 100
```

**Individual retention index:** `clamp(100 minus retention penalty, 0, 100)`.
**Individual breach tests:** retention breach when the index is below 70;
performance breach when the score is below the floor, or the review is missing,
or the review age exceeds the window; contract breach when terms are verbal, or
notice is below the floor, or probation runs past three months.

**Weighted individual risk score, 0 to 100.**

```
weight sum = max(1, contract weight plus performance weight plus retention weight)
risk = clamp((contract component times contract weight
           plus performance component times performance weight
           plus retention penalty times retention weight) divided by weight sum, 0, 100)
```

**Register-level Contract Risk Score, the breach-share score, 0 to 100.** This is
not the mean of the individual scores. It is the weighted share of people who
breach each rule set:

```
score = (contract breaches divided by n times 100 times contract weight
       plus performance breaches divided by n times 100 times performance weight
       plus retention breaches divided by n times 100 times retention weight)
       divided by weight sum
```

**Bands and thresholds.** Risk band is High at or above the alert threshold,
Watch within 20 points below it, Low beneath that. Retention band is Stable at
75 or above, Watch at 60 to 74, At risk below 60.

## Step 4b. The employee data format

The dashboard needs no HRIS. A single table with these fields is enough to
compute all four cards. Keep it flat, keep dates ISO, keep one row per person.

### Twelve fields

| Field | Type | Rule |
| --- | --- | --- |
| employee_id | string | Unique, required. Duplicates are rejected, not merged |
| name | string | Required |
| role | string | Free text |
| department | string | Free text, drives the department chart and switch |
| salary | integer | PKR per month, zero or above |
| start_date | date | `YYYY-MM-DD` |
| contract_status | enum | permanent, probation, contract or verbal |
| notice_period_weeks | integer | 0 to 26. Below four for permanent staff raises a flag |
| performance_score | integer | 0 to 100 |
| last_review_date | date or empty | `YYYY-MM-DD`. An empty value means never reviewed |

### Eight validation rules the importer enforces

| # | Rule |
| --- | --- |
| 1 | `employee_id` unique, non-empty. Duplicates are rejected, not merged |
| 2 | `salary` integer PKR per month, zero or above |
| 3 | `start_date` and `last_review_date` in `YYYY-MM-DD`. An empty review date means never reviewed |
| 4 | `contract_status` one of permanent, probation, contract, verbal |
| 5 | `notice_period_weeks` integer 0 to 26. Below four for permanent staff raises a flag |
| 6 | `performance_score` integer 0 to 100 |
| 7 | `manager_id` either empty or an existing `employee_id` |
| 8 | `risk_flags` semicolon-separated tokens, preserved as typed and extended by the model |

Importer behaviour around the rules: a header row and at least one data row are
required; every one of the twelve columns must be named in the header, and a
missing column is listed by name. Rows are quoted-comma aware. Errors are
reported per row and prefixed with the row number; `manager_id` is cross-checked
against the identifiers in the same file. On any error nothing loads and the
first four problems are shown with a count of the rest. On success the preview
replaces the fictional register, keeps an undo point, resets the department
filter and reports the loaded count.
